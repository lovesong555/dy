## 1. 用户的要求（按时间，后面的覆盖前面的）

### 1.1 账号和人设
- 账号名 **宋玉**，抖音，**不露脸**。
- 人设：**从一条资讯看清一门生意**，只用公开资料。
- **绝不写**“我在现场 / 港口看到”（身份保护）。
- 视频分三类：**人物 / 资讯 / 产业链**。
- **只出竖版**（1080×1920）。

### 1.2 品牌模板（固定）
- 左上角只放“宋玉”；**最右上角**放分类标签（黑底白字）；**不放标语**；不出现期数。
- 米白底 #F3EEE4，墨色 #141210，朱红 #C8372D；字体只用思源黑体 / 思源宋体（SIL OFL）。
- 顶部章节进度条，按配音时长自动分段。
- 真实素材优先：视频铺满画面宽度，照片完整显示不裁剪，网页截图按整行裁、静止、荧光笔标关键句，每个素材都写出处。
- 人物类视频：人物第一次出现先用“？”盖住，讲到“前世今生”这类章节时再揭开。

### 1.3 写稿
- 钩子只要求“真实、有关、有逻辑”；用户给的钩子默认保留，改动要最小（见 `改稿与意见权衡.md`）。
- 收到任何意见（用户的、其他 AI 的），先分类、权衡，再动手；不盲从，也不改过头。
- 配音前查多音字（`check_pron.py`），配完用语音识别核对（`check_asr.py`），交付前人耳听一遍。

### 1.4 选题（这是现在最大的问题，见第 2 节）
- 主线是“出口追链”：从海关、边检、口岸、港口的一条官方稿出发 → 查出货是谁的 → 当地卖多少钱、做什么项目 → 企业在当地的布局。样板是烟台 / 蓬莱港区那几期。
- 也可以拆**行业、商业模式、商业架构**，可以参考外国（日本艺人经济等）。
- 用户的原话：**“宣传稿里直接有企业的，拆出来就是企业出海流程的复述，没有信息差”**。2026-10-25 给的 10 条选题，用户一条都不满意。
- 用户要求：**写之前先深入调研大博主**：每位博主扒 30–40 期，标出选题、叙事、素材、画面安排、人设怎么维持、怎么围绕选题输出观点。要回答“我们凭什么比别的泛经济博主、比别人用 AI 写的强”。

### 1.5 协作方式
- 每做完一步都提交并推送到 `claude/douyin-topics-optimization-28ebdu` 分支；不开 PR。
- 用户的意见要写进 Skill，不能只留在聊天里。
- 遇到问题先查 `排错记录.md`，再去 GitHub 搜 issue，解决后写回排错记录。
- 省 token：用一条命令出片、只重做改过的部分、审片只看一张拼图、长任务放后台。

## 3. 环境和工具

### 3.1 仓库结构
- `.claude/skills/douyin-midvideo-script/`：Skill 本体；
- `交接/`：交接文档、发布信息、出片流程（`试制段流程/`）、工具（`工具/`）；
- `图表源码/`：画面引擎 `scene.html`、封面 `cover.html` + `covers.json`、头像 `avatar.html`、原文截图 `evidence/`（`proof07.json` 等记录高亮位置）、照片 `photos/`、视频帧序列 `clips/`；
- `研究记录/`：博主学习、选题调研；
- `样片/`：成片、封面、账号素材。

### 3.2 一条命令出片（竖版）
```bash
# 前提：仓库根目录；edge-tts 在 PATH 里（pip install edge-tts）；Node + Playwright；ffmpeg（带 libass）
python3 交接/试制段流程/make_video.py <分镜.json> <输出目录> <成片名>
```
- 自动做：读音检查 → 配音（文字没变就复用）→ 写分镜 → 只渲染改过的镜头（并行）→ 合成字幕和配音 → 输出 `审片_竖版.jpg`。
- 本地网页服务（8765 端口，目录 `图表源码/`）和 `src` 软链接会自动建好。
- 分镜 JSON 格式见 `交接/试制段流程/人物_李一男.json`：顶层写 `template: songyu`、`brand`、`cat`；`chunks` 里每句有 `vo`（口播）和 `scene`（镜头）；要改读音就加 `tts` 字段。

**镜头类型**（`图表源码/scene.html`）：
- 真实素材：`clip`（视频帧序列）、`photofull`（完整照片，可加 `mask` / `reveal`）、`page`（网页原文整行裁剪）；
- 数据和关系：`pie`、`quote`（可加 `stamp`）、`terms`、`split`、`bignum`、`person`、`compose`、`route` 等。

**校对**：
- `python3 交接/试制段流程/check_pron.py <分镜.json>`：配音前查易读错的词；
- `<装了 faster-whisper 的 python> 交接/试制段流程/check_asr.py <分镜.json> <配音.wav> <whisper 模型目录>`：配音核对。

### 3.3 其他工具（`交接/工具/`）

| 文件 | 用途 |
|---|---|
| `bili.py` | B 站接口（WBI 签名）：`search` 搜视频，`user` 列博主视频（可能被风控 -352，就改用 search） |
| `dlv.py` | 下载 B 站视频（不登录最高 480p） |
| `asr.py` | faster-whisper 批量转写 |
| `capm.mjs` | 按手机宽度截网页原文并记录关键句位置（`VW=440` 截 SEC 这类英文文件） |
| `capture_desktop.mjs` | 桌面宽度截图 |
| `still.mjs` | 每个镜头截一张静帧（先看静帧再出视频） |
| `cover.mjs` / `avatar.mjs` | 渲染封面 / 头像 |
| `ass2srt.py` | 字幕转 srt（给剪映用） |
| `comtrade.py` | 联合国贸易数据月度查询（按国家、HS 编码），做镜像对账 |

**这些工具里的路径是我当时的临时目录，换了环境要改。**

### 3.4 已知的坑（详见 `references/排错记录.md`）
- Playwright 自带的 Chromium 放不了 H.264 视频 → 先用 ffmpeg 抽成 JPG 帧序列。
- 等待命令不要用 `pgrep -f` 轮询，会匹配到自己 → 用进程句柄 `wait()`。
- edge-tts 不支持指定读音 → 换词，或者用 `tts` 字段写同音字。
- 海关官网（*.customs.gov.cn）对自动访问一律拦截（HTTP 412）→ 用政府网站、党报、新华社、中新社的转载。
- YouTube 下载被拦（要登录）。
- 网页搜索整个会话有 200 次上限，几个助手共用，容易提前用完。

## 4. 派助手（子代理）的方法和提示词

### 4.1 原则
- **按“地区 + 信源类型”或“按博主”分工**，每个助手负责一条完整链路，不把一件事拆给几个人接力。
- **长说明写进文件**（例如 `00_任务说明.md`），给助手的提示词只说“先读这个文件 + 你负责哪部分”。这样省 token，换 AI 也能直接复用。
- 助手把结果**写进文件**，回复里只报“文件路径 + 几行核心发现”。
- 主控负责汇总、亲自打开起点原文核对、去重、给用户结论。

### 4.2 用过的提示词

**A. 出口追链选题**（2026-10-25，6 个助手，按区域）：
- 提示词要点：
  - 账号人设 + 你负责的范围（华南 / 华东 / 陆路口岸边检 / 北方 / 企业反查）；
  - 好选题的七条标准（见 `references/选题_出口追链.md`）+ 避开已经做过的题；
  - 先广撒网找 15 条以上候选 → 深挖 4–5 条 → 留 3–4 条；
  - 每一环都要打开原文核实，只在搜索摘要里看到的标【未打开核实】；
  - 输出格式：题目 / 起点原文 / 货主证据 / 链条（每环带证据等级）/ 价格 / 为什么是现在 / 缺的一环 / 自评。
- 结果在 `研究记录/选题_2026-10_出口追链与行业拆解/A–F.md`。**用户的反馈是不满意**（见 1.4），下次不要原样再派。

**B. 行业和商业模式选题**（1 个助手）：
- 起点是外媒或国内财经媒体的近期新闻；拆成 3–5 层（谁出钱、谁出力、钱怎么分）+ 历史脉络 + 为什么是现在 + 和中国对照。

**C. 博主选题研究**（2026-10-25，5 个助手，每人 2 位博主）：
- 提示词：“先读 `研究记录/博主学习/选题研究_2026-10/00_任务说明.md`，按里面的要求研究 <博主 A>、<博主 B>，两人各写一个文件；已有材料在 <路径>；最后的回复只要文件路径 + 5 行以内的核心发现。”
- 第 5 个助手另外负责找 3–5 个产业链 / 出口 / 供应链方向的竞品账号。
