## 一、用户是谁、要做什么（最新目标）

用户做一个**不露脸**的抖音 / B 站财经、产业链中视频账号，每期 4–5 分钟。

**人设**：看几条公开新闻、公众号、公告，就能用申论的思路拆解，反推加正推，把整条产业链讲透，像“亲临过一样的高手”。
**身份保护**：绝不说“我在港口 / 现场看到”。

**最新目标**（按 2026-10-24 最后几条消息，越靠后越新）：

1. **往真实制作走**：不要再只交文档和静态图，要交可以直接拼进剪映的动画镜头。
2. **两种画幅，都要能用**：
   - **横屏**：每一期都要有，一期 **10–20 个镜头、每个 3–4 秒**，拼起来就是成片画面。目前只做了第08期（17 个镜头）和第04期（4 个镜头）的样片。第01–07期还没有横屏镜头。
   - **横屏风格**：用户觉得“偏橙色底”的档案纸风格“还可以”。要去搜“泛知识”视频里有没有更好的暖色风格；没有就定这个。调研正在进行，见第四节。
   - **竖屏**：路线动画（A 点到 B 点）用户很满意，但**数据全是柱状图太呆**。要用当期故事里的东西来表达差距，例如：
     - 讲纸浆，就把纸叠起来，一叠多、一叠少；
     - 讲牛奶和大豆，就用大豆的实物照片变成牛奶的实物照片，大豆少和大豆多对比。
   - 竖屏要“再完善，并确定用这种风格还是换风格”。
3. **整体设计要自己先审**：用户提出“一般是横屏做底，竖屏作为其中的展示”。做法是：
   - 先做一条十几秒到一分钟的 MP4；
   - 自己抽帧审一遍，确认能用；
   - 再批量做全部期数。
4. **文案**：要有逻辑、循序渐进、反差鲜明、不幼稚、不像 AI。写法见 Skill v4 第 12 节。
5. **字体和素材必须能商用**，不能让人找上门。
6. **持续交付**：所有东西都放进 GitHub 仓库，方便别的账号接着做。

## 二、Skill 是什么（最新版 v4）

- **位置**：`.claude/skills/douyin-midvideo-script/SKILL.md`。在 Claude Code 里说“写抖音文案”“中视频脚本”就会自动调用。
- **用途**：把一个产业链、财经或人物选题，写成 4–5 分钟口播（1300–1600 字）。同时产出三段式分镜、章节条、证据截图清单和动态图表清单。
- **结构**：

| 节 | 内容 |
|---|---|
| 0–2 | 学习样本、11 位博主各学一招、账号定位 |
| 3–8 | v2 的结构模板（一钩 + 三段 + 一收）、钩子库、转场句库、画面系统、写作流程、标题公式 |
| 9 | 题材分型 A–F，不同行业怎么套 |
| 10 | 信源申论拆解法，写稿前必做：谁做了什么、什么效果 → 相关什么、替谁解决了什么 → 为什么需要 → 为什么是这个单位、上面是什么政策 |
| 11 | 不出镜的呈现形式；虎嗅式档案卡；**字体版权硬规则** |
| **12** | **v4 核心：推理链写法**。来自 12 位博主 87 期新视频的二十个推理动作（开题 / 反推 / 正推 / 检验收束）、4–5 分钟串法、9 条防幼稚和防 AI 腔的硬约束、6 个改稿自检问题。**写稿时第 12 节优先于第 3–5 节** |

- **示范**：手册第08期（张茵 / 玖龙纸业）是按 v4 写的正式稿，附了同题材的 v3 对照稿和逐项对比表。

## 三、最新思路

### 3.1 文案

- 骨架是**一条链的三步**，不是三个并列问题。例如：“链是怎么搭起来的 → 谁把它剪断了 → 现在谁在补”。
- 开题用**两个同期、有出处、放在一起说不通的数字**，例如：玖龙利润 +83.8%，家族订单 −75%。
- 中段做三件事：
  - **反推**到具体文件或必要条件；
  - **排除**替代解释；
  - **正推**钱和货的路线，每一层都点名主体、给出数字、说明“凭什么”。
- 收尾讲**结论成立的条件**，再留一个两难。不上价值，不喊口号。
- 证据分三档说：硬数据带出处；推断明说“这是我的一种解释”；传言当八卦。

### 3.2 画面和制作（正在做）

- **横屏是母版（1920×1080）**：每期 10–20 个 3–4 秒的动画镜头，按口播顺序在剪映里拼接。
- **竖屏有两种用法**：
  1. **横转竖**：横屏镜头放在 9:16 画布中间，上面放标题，下面留字幕区。模板是 `图表源码/vframe.html`，渲染脚本是 `图表源码/渲染脚本/mk_vframe.mjs`。这是用户提的“横屏做底”的思路。
  2. **竖屏原生镜头**：同一个引擎加 `o=v` 参数就能出，适合单独剪成短视频。
- **分镜动画引擎**：`图表源码/scene.html` + `图表源码/scenes/<期号>.json`。每期一个 JSON，每个镜头一行，写清 type 和数据。已经有 18 种镜头类型：

| type | 做什么 | 例子 |
|---|---|---|
| title | 大标题 | 开场 |
| bignum | 大数字计数 | +83.8% |
| stack | **纸张 / 令纸叠高对比**（用户点名要的） | 328 亿 vs 79.8 亿 |
| quote | 一句话卡 | “说不通” |
| terms | 词条演变 | 废纸 → 废纸 + 浆 → + 木片 |
| chapter | 章节卡 | ① ② ③ |
| person | 人物标签卡 | 张茵 |
| route | 纸面地图 + 航线 + 船移动 | 美国 → 东莞 |
| picto | 象形图，N 个里 k 个高亮 | 10 包里 8 包 |
| decree | 政策文件 + 盖章 | 四部委公告“禁” |
| pile | 一堆东西逐年减少 | 废纸进口归零 |
| grow | 一堆东西越堆越高 | 木浆产能 |
| split | 当年 vs 现在左右分屏 | 2006 vs 2026 重庆 |
| coins | 金币堆 + 计数 | 一年 5600 万美元利息 |
| conditions | 收尾的成立条件 | 两个条件 |
| morph | **实物照片链**（用户点名要的） | 大豆 → 奶牛 → 牛奶 |
| beans | **豆子点阵，很多颗里只有几颗** | 500 颗里 1 颗 = 0.2% |
| glass | 一杯奶按比例分层 | 饲料占 77% |

- **风格**：
  - 横屏和镜头引擎目前用**“档案纸”暖色版**：米白纸 #EFE9DD、朱红 #C8372D、墨色 #1d1a16、思源宋体标题。
  - 已有的 50 张数据图是**毛玻璃深色版**：石墨底、主色蓝、单一暖色强调。它是 v4 包里的图表，可以继续用作竖屏数据卡，或者统一改成纸面风格。**最终风格等暖色风格调研出结论后定**。
- **“用故事元素代替柱状图”的规则**：每期至少一半的数据镜头，用当期故事里的实物来表达：
  - 纸 → 叠纸；
  - 大豆 → 豆子；
  - 挖掘机 → 挖掘机图标排队；
  - 牛奶 → 杯子；
  - 车 → 车流；
  - 变压器 → 排队等待的格子。
  - 柱状图只在对比的东西没有实物可用时才用。
- **版权**：
  - 图标全部原创 SVG。
  - 字体只用思源宋体 / 思源黑体（SIL OFL）。
  - 照片只用公有领域或 CC，画面左下角署名，完整署名在 JSON 的 `credit` 字段。
  - 新加的两张照片：
    - `photos/soypods.jpg`：USDA，公有领域；
    - `photos/milk.jpg`：Santeri Viinamäki / Wikimedia Commons，CC BY-SA，版本以 Commons 文件页为准。

### 3.3 出镜形式

- 主形式是不出镜，用“素材 + 精良包装”。辅助形式是一个原创卡通形象小窗，占全片 15–25%。不用写实数字人。
- 依据：17 个账号的关键帧形式研究，加上虎嗅 35 条视频、1251 帧的统计。
  - 虎嗅的“纯白屏 + 卡通”只出现在九叶刀栏目 2025 年的一段时间，全号主流是资料片和深色大数字。

## 六、怎么继续（命令）

```bash
# 0. 依赖：Node 22 + Playwright（Chromium）、ffmpeg、Python3 + Pillow、pandoc、python-docx、LibreOffice（转 PDF 预览）
# 1. 起本地服务器（所有 HTML 都要通过 http 打开）
cd 图表源码 && python3 -m http.server 8765 &
# 2. 渲染脚本默认在“图表源码的上一级”运行，并读取 src/ 目录。最简单的做法是建一个软链：
cd .. && ln -s 图表源码 src
# 3. 渲染一期镜头（h 横屏，v 竖屏，hv 都要）。输出每个镜头的 MP4、首尾帧、静帧，以及整期预览 MP4
node 图表源码/渲染脚本/render_scene.mjs 08 样片/08 hv
# 4. 只截静帧检查（很快）。静帧输出到当前目录下的 sc/
node 图表源码/渲染脚本/shot_scene.mjs 08 h 1 2 3
# 5. 数据图（毛玻璃版）：node 图表源码/渲染脚本/render.mjs src out --anim [前缀]
# 6. 手册：源文件在 交接/手册源文件/*.md，构建脚本在 交接/手册构建/（build.py → pandoc + ref.docx → post.py）
#    build.py 和 sync.sh 里的 SP 路径同样写死成旧 scratchpad，改成自己的工作目录后再跑
```

**踩过的坑**：
- B 站接口：投稿列表 `space/wbi/arc/search` 经常返回 412 / -352。可以改用合集接口 `seasons_archives_list`、相关推荐 `archive/related`，或者按播放量排序搜索；请求要串行、带 sleep。
- Wikimedia：API 会限流。下载图片用 `https://commons.wikimedia.org/wiki/Special:FilePath/<文件名>?width=1600`，并带一个自报身份的 UA，例如 `DyChartFetcher/1.0 (https://example.org/contact; research@example.org)`。
- Flickr 图片直链会被 429 封 IP；Openverse API（api.openverse.org）可以用来找 CC 图片。
- SEC：必须带公司加邮箱格式的 UA，否则被拦。13D 的可读版是 `xslSCHEDULE_13D_X01/primary_doc.xml`。
- 港交所 PDF 用 pdfminer / pdftotext 提取，中英文两版交叉核对。
- 字体：只用 `图表源码/` 里随附的思源字体，HTML 里用 `@font-face url()` 写死；不要依赖系统字体，系统里的回退字体可能没有商用授权。
- 推送：之前 GitHub App 没有仓库权限，返回 403；2026-10-24 已经恢复。
