# 排错记录（遇到问题先查这里，再去 GitHub 搜）

## 遇到问题的固定步骤

1. **先看这份记录**：同样的问题出现过，就直接用记下的解法。
2. **再去 GitHub 搜**：搜 `<工具名> <报错关键词> issue`（例：`playwright chromium h264`、`edge-tts phoneme`），看 issue 里别人怎么解决。
3. **还没解决**：缩小到最小例子（只渲染 1 个镜头、只配 1 句音），定位原因后再全量重跑。
4. **解决后写回这里**：现象 / 原因 / 解法 / 出处。下次就不用再查。

---

## 1. 视频镜头渲染超时（页面一直不 ready）

- **现象**：`clip` 镜头卡在 `waitForFunction` 30 秒超时。
- **原因**：Playwright 自带的是开源 Chromium，不带 H.264 / AAC 解码（专利授权原因），MP4 里的视频放不出来。
- **解法**：先用 ffmpeg 把视频片段抽成 30fps 的 JPG 序列（`图表源码/clips/<名>/0001.jpg…`），`clip` 镜头逐帧换图。也可以转成 WebM/VP9，或者用系统里装的 Google Chrome（`channel: 'chrome'`）。
- **出处**：[CEF issue #3559](https://github.com/chromiumembedded/cef/issues/3559)，以及 Chromium 关于专有编解码器的代码评审。

## 2. 渲染早就完成，但“等待渲染结束”的命令一直不结束

- **现象**：各镜头都已经 `done`，命令却一直跑到超时，成片没合成。
- **原因**：用 `while pgrep -f "render_scene.mjs 07seg"` 等待，外层 shell 自己的命令行里就含这串文字，pgrep 一直能匹配到“自己”。
- **解法**：不用 pgrep 轮询。`make_video.py` 用 `subprocess.Popen` 启动渲染，再 `wait()` 等进程句柄结束。
- **出处**：已知问题，见 claudeissues.com 上的 [#60716](https://claudeissues.com/issue/60716-bug-agents-emit-self-matching-pgrep-f-polling-patterns-that-deadlock-background)、[#52328](https://claudeissues.com/issue/52328-bug-monitor-until-loop-self-matches-when-model-uses-pgrep-f-cmdline-as-its-check)（Claude Code 问题追踪），以及 `pgrep` 手册。

## 3. 配音读错多音字（“同行”读成 tóngxíng）

- **原因**：edge-tts 的免费接口不支持 SSML 的 `<phoneme>` 标签，没法直接指定读音。
- **解法**：
  - 配音前跑 `交接/试制段流程/check_pron.py`（`make_video.py` 会自动跑）；
  - 能换词就换词（同行 → 竞争对手，一只 → 一个）；
  - 换不了，就在这一句加 `tts` 字段写同音字或汉字数字，字幕仍显示原文；
  - 新发现的错词加进 `check_pron.py` 的 `RISK` 词表。
- **出处**：[rany2/edge-tts issues](https://github.com/rany2/edge-tts/issues)（没有 phoneme 支持的记录）；腾讯云 TTS 文档里有 `<phoneme>`，以后换付费配音时可以用。

## 4. 网页截图把字切断（“一度被认为接班人”只显示一半）

- **原因**：旧的 `proof` 镜头以高亮为中心按固定宽度裁剪，左右两边的字被切掉。
- **解法**：用 `page` 镜头，手动给 `crop`（整栏宽度、完整的几行），整体缩放进框里。

## 5. 无头浏览器截图时图片还没加载完（出现空白框）

- **解法**：镜头里对图片调用 `img.decode()`，加载完再标记 `__ready`（`page`、`proof` 已经这么做）。
